About the Project

Why this project is needed.

Edible surplus food can have a short usable life. When coordination depends on emails, messages, and informal communication, it can be difficult to know what is available, whether it is eligible, who can accept it, and whether pickup can happen in time.

!

What is happening now

Information can be scattered across informal channels, making time-sensitive redistribution harder to coordinate.

↔

What we are proposing

A common workflow for recording surplus food, checking eligibility, coordinating recipients and pickups, and tracking outcomes.

✓

Why it could help

Better visibility, less manual coordination, clearer records, and reduced avoidable disposal of edible food.

How the System Would Work

How the proposed system would work.

01

Record surplus

Food-service staff enter food type, quantity, availability, pickup location, and time information.

02

Check eligibility

Required donation and food-safety information is reviewed before food is offered to recipients.

03

Recipient response

Approved recipient organizations review available donations and decide whether they can accept them in time.

04

Coordinate pickup

Pickup personnel receive collection and delivery information and confirm transfer steps.

05

Track status

Each donation is followed through the redistribution process using a clear current status.

06

Support reporting

Completed records can support food-waste, sustainability, and program reporting.

Project Scope

What is included in the project.

The project is limited to systems analysis and design for an initial UVic-campus context. It is not a production deployment.

In scope

  • Analyze selected UVic redistribution processes
  • Define system requirements
  • Develop use cases
  • Develop data and process models
  • Create a UI prototype
  • Document and present the proposed system

Out of scope

  • Production deployment
  • Long-term system operation or maintenance
  • Expansion outside the initial campus environment
  • Direct community-member use in the initial version
  • Direct B2P or P2P redistribution

What We Are Delivering

What we are creating for the project.

For this course, we are focusing on the analysis and design of the proposed system. These are the main things we will create.

R

Requirements and Use Cases

We will define what the system should do, what users need from it, and how the main users would interact with it.

D

Data and Process Models

We will show what information the system needs to keep and how the redistribution process moves from one step to another.

UI

UI Prototype

We will create mock-ups of the main screens to show how food-service staff, recipients, and pickup personnel could use the system.
